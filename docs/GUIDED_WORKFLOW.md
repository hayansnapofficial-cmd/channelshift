# 기능 선택과 제작 공통 가이드

v0.2.3부터 제공하는 기능입니다. 기존 프로젝트의 요구사항·선택·승인 이력을 보존합니다.

## 직원이 사용하는 순서

1. 실제 고객 원문으로 프로젝트를 만듭니다.
2. 문의, 예약, 회원, 결제, 콘텐츠, 알림, 디자인, 검색·공유의 선택 카드를 확인합니다. 각 카드에는 선택지 설명과 예상 작업 규모가 있습니다. 금액이나 일정은 자동 견적하지 않습니다.
3. 버튼으로 선택하고 바로 아래 설명란에 예외나 원하는 상황을 적습니다. 설명란은 항상 열려 있습니다.
4. **잘 모르겠어요**는 현재 선택과 설명을 저장한 뒤 Codex에 요구사항 정리와 선택 추천을 요청합니다. 추천 이유와 고려할 점을 확인하고 **이 추천으로 선택**을 누릅니다. 이 클릭은 편집 중인 선택을 바꿀 뿐, 고객 승인이나 단계 승인으로 기록되지 않습니다. 근거가 부족하면 추천 대신 확인 질문을 받을 수 있습니다.
5. 저장하고 다시 정리한 뒤 확인 질문에 답합니다. 미선택, 잘 모르겠어요, 나중에 결정 항목이 남아 있으면 요구사양을 확정할 수 없습니다. 기본 검색·공유 설정과 기존 운영·정책 일곱 항목은 선택 기능에서 제외할 수 없습니다.
6. 요구사양 확정 후 화면 설계부터 단계별 생성·수정·검수를 이어갑니다.

선택과 설명은 명시적으로 저장합니다. 같은 탭에서 프로젝트를 바꾸거나 작업 결과를 기다리는 동안 입력 초안을 보존합니다. 브라우저를 종료한 뒤에도 남겨야 하는 내용은 저장해야 합니다. 다른 요청이 먼저 저장되었으면 충돌을 표시하고 재확인한 뒤 저장합니다.

## 추천과 조사·점검의 역할

| 기능 | 실행 방식 | 결과의 효력 |
| --- | --- | --- |
| 기능 추천 | 본인 Codex로 원문·작업자 선택·설명을 분석 | 제공된 선택지 안의 제안, 직접 수락 필요 |
| 참고 사이트 수집 | 입력한 공개 HTTPS URL을 서버의 수집 서비스로 조회 | 별도 출처 기록, 고객 원문으로 편입하지 않음 |
| 요구사항 근거 점검 | 원문과 요구사항 후보를 서버 판단 서비스로 비교 | 사람 검토용 의견 |
| 선택 내용·참고자료·산출물 점검 | 명시적인 점검 버튼으로 현재 자료를 전송 | 가능성과 불확실성을 표시, 승인 권한 없음 |

Jev/TypeSafe는 선택·관련성·의미 일치 판단을 보조하고, Apify는 참고자료를 수집합니다. UI에서는 사용자가 수행할 작업명으로 표시합니다. 판단 서비스는 생성된 코드를 실행하지 않으며, 결과는 테스트 통과·보안 보증·고객 승인으로 취급하지 않습니다. 전체 참고 페이지 대신 제한된 발췌문을 보내는 경우 불완전한 근거로 표시합니다. 산출물 점검은 선택한 한 단계의 파일을 대상으로 합니다.

공용 점검은 기존 요구사항 검토 사용량 한도를 공유합니다. 클릭 없이 주기적으로 유료 호출하지 않습니다. 서버 API 자격증명은 브라우저, 산출물, Codex 입력에 전달하지 않습니다. 자료나 선택을 바꾸면 이전 점검은 이전 입력 기준으로 남습니다.

## 서버 공통 제작 기준

`production_guides.py`는 디자인, 구현, 문서 검수 기준을 버전별로 보관합니다. 새 프로젝트는 기준의 버전과 내용 해시를 고정하고 생성 입력과 검수 근거에 연결합니다. 요구사항 정리, 화면 설계, ERD, API, 백엔드, 프론트 생성 프롬프트에 단계별 기준을 넣습니다.

- 디자인: 브랜드 근거, 대표 화면, 타이포그래피·간격·색상, 반응형, 접근성, 빈 화면·오류 상태.
- 구현: 승인된 요구와 계약 연결, 입력 검증과 권한, 실패 처리, 테스트 근거, 구현 한계.
- 문서 검수: 요구 출처와 반영 범위, 미결정 항목, 변경 이유, 실행한 검사와 아직 하지 않은 검사 구분.

이 기준은 자동 다운로드한 외부 스킬을 실행하는 방식이 아니라 저장소에서 검토·버전 관리하는 공통 지침입니다. 실제 디자인 품질이나 실행 안정성은 산출물 미리보기와 단계 검수가 계속 필요합니다. 생성 앱 실행·인수 검사·운영 배포는 기존 구현 범위와 같습니다.

## 데이터와 기존 프로젝트

기능 카탈로그와 선택 이력은 프로젝트별로 보관합니다. 현재 선택만 다음 분석에 반영하되 이전 선택과 사람의 설명을 이력에서 지우지 않습니다. 설명은 고객 원문과 구분된 작업자 입력입니다. 자동 추천을 고객 요청의 근거로 사용하지 않습니다.

기존 프로젝트를 여는 것만으로 새 카탈로그나 가이드를 강제로 적용해 승인 결과를 무효화하지 않습니다. 새 프로젝트에 새 흐름을 기본 적용합니다. 변경한 요구·선택·산출물에 의존하는 후속 단계는 재검토해야 합니다.

## 기능 선택 화면 회귀 검사

저장소 루트에서 Node.js 기본 모듈만으로 실행합니다. 별도 패키지 설치나 외부 서비스 호출은 없습니다.

```sh
node --test tests/test_studio_guidance.mjs
```

실제 편집기 모듈을 작은 DOM 어댑터에 연결해 프로젝트 이동·폴링·실패 시 입력 보존, 충돌 확인, ‘잘 모르겠어요’ 콜백, 추천의 명시적 수락과 미저장 상태, 오래되거나 제외한 항목의 추천 차단을 검사합니다. 화면 배치와 실제 서버 연결은 별도 브라우저 검수 대상입니다.
