# ChannelShift 0.2.2

회원 로그인·저장 한도 보호와 제작 공정의 연결 검사를 강화한 배포입니다.

- 계정별 제한에 걸린 로그인 요청이 다른 회원의 로그인 예산을 소모하지 않도록 분리했습니다. 프록시의 접속자 IP를 명시적으로 신뢰하는 설정을 함께 적용합니다.
- 설계 저장 전에 회원별 파일 수·총용량을 원자적으로 검사합니다. 기존 파일은 삭제하지 않습니다.
- 승인된 화면 설계와 해시를 ERD 생성 입력·이력에 고정합니다.
- API·필드·화면 참조, 백엔드 경로·함수·테스트 정의, 프론트 화면/API 선언을 검사합니다.
- ERD 필드 변경의 영향 정보를 현재 산출물에서 불러오고, 수정 이유를 작업 이력에 남깁니다.

## 기존 프로젝트

회원 계정, 프로젝트 파일, 작업 이력과 연결 설정을 보존합니다. 검사 프로필 v2가 적용되면 기존 산출물 승인은 재검토 대상이 됩니다. 상위 단계를 확인한 뒤 기존 파일을 이유와 함께 수정·재검사할 수 있습니다. ERD는 현재 승인된 화면 설계에서 다시 생성합니다. 새로운 필수 연결 파일과 API 확장은 [산출물 계약](PIPELINE_CONTRACTS.md)을 따릅니다.

## 검증과 실행 범위

패치 테스트 530개를 Windows와 Linux에서 수행했습니다. Windows 525개 통과·5개 제외, Linux 529개 통과·1개 제외입니다. 합성 프로젝트의 브라우저 저장·영향 표시·수정 이유 이력·검수 무효화도 확인했습니다.

생성된 코드와 테스트는 소스로 검사하며 실제 실행하지 않습니다. 영향 개수는 검사된 연결 선언을 기준으로 합니다. 실제 고객 앱의 인수 검사·운영 배포 완료를 뜻하지 않습니다. 서버 업데이트만으로 이메일 발송이나 유료 공급자 호출을 수행하지 않습니다.

## 배포 파일

- `channelshift-0.2.2-py3-none-any.whl`: 프로그램·회원 서버·MCP 패키지.
- `channelshift-0.2.2.tar.gz`: 소스, 테스트, 문서와 라이선스.
- `channelshift-skill-0.2.2.zip`: 스킬과 같은 버전의 wheel.
- `SHA256SUMS.txt`: 배포 파일 확인값.

운영 적용은 [배포 안내](DEPLOYMENT.md)의 프록시 선행 적용·보호된 백업·상태 검증 절차를 따릅니다. 이전 이미지와 데이터 백업을 보존합니다. 롤백은 우선 이전 앱 이미지로 전환하고, 데이터 복원은 배포 이후 새 작업 유무를 확인한 뒤 별도로 판단합니다.
