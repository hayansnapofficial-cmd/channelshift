# 회원 가입·이메일 인증·로그인

이 기능은 명시적으로 실행하는 **로컬 회원 모드**다. 기존 단일 운영자 모드의 저장소·프로젝트·Codex 로그인·API 비밀값을 회원에게 자동으로 넘기지 않는다. 인터넷 공개 서비스, 조직 권한 관리, 운영 수준의 계정 복구가 완성되었다는 뜻은 아니다.

## 현재 이용 흐름

1. `python -m channelshift.member_web --port 5189`로 별도 회원 서버를 실행하고 `http://127.0.0.1:5189/login`을 연다. 회원 서버는 127.0.0.1에만 바인딩한다.
2. 아이디·이메일·비밀번호로 가입한다. SMTP가 설정되지 않았으면 `email_not_configured`로 가입을 거절한다. 설정 여부는 발송 성공이나 배달 성공을 보장하지 않는다.
3. 이메일의 인증 링크를 열고 사용할 비밀번호를 다시 설정한다. 이메일 소유자가 확정한 비밀번호로 기존 임시 비밀번호를 교체한다. 누군가 타인의 이메일로 먼저 가입했더라도 그 사람이 정한 비밀번호를 활성화하지 않는다.
4. 인증이 완료된 계정으로 로그인한다. 로그인 성공 시 새 세션을 만들며, 로그아웃하면 그 세션을 서버에서 폐기한다.

가입·재발송 응답은 계정 유무를 공개하지 않는 공통 메시지다. 미인증 일반 회원은 로그인할 수 없다. 로컬에서 직접 생성한 마스터는 아래의 별도 생성 기록으로 로그인한다. 이메일 링크는 30분 동안 한 번만 유효하며, 재발송하면 이전 링크를 폐기한다. 링크만 열어서는 계정 상태가 바뀌지 않으며 새 비밀번호와 함께 제출해야 한다. 메일에는 계정명과 직접 가입하지 않았으면 무시하라는 안내를 포함한다.

아이디는 ASCII 영문·숫자·밑줄 4~32자이며 공백을 정리하고 소문자로 저장한다. 이메일은 단순 ASCII 주소 형식을 검증하고 앞뒤 공백·대소문자를 정규화하여 고유하게 저장한다. 국제화 이메일·별칭 제공자별 정규화는 지원하지 않는다. 일반 회원 가입·이메일 인증·로컬 마스터 최초 생성의 비밀번호는 모두 NFC 정규화 후 8~128자다. 로그인은 1~128자 입력을 저장된 비밀번호와 대조한다. 유니코드를 허용하고 NUL과 잘못된 유니코드는 거절한다. 정기 강제 변경이나 문자 종류 조합 규칙은 넣지 않았다.

미인증 일반 계정의 예약은 24시간 후 만료된다. 다음 인증 작업의 정리 과정에서 삭제하여 아이디·이메일을 다시 사용할 수 있게 한다. 로컬 마스터와 관리자가 정지한 계정은 이 삭제 대상에서 제외한다. 인증 링크의 만료는 별도로 30분이다. 미확인 사용자가 예약한 아이디에 대한 소유권 분쟁이나 이미 인증된 계정의 복구는 별도 운영 절차가 필요하다.

## 로컬 마스터 생성과 회원 관리

운영자가 프로젝트 폴더의 대화형 터미널에서 다음 명령을 실행한다. 예시 아이디와 이메일은 사용할 값으로 바꾼다.

```powershell
.\.venv\Scripts\python.exe -m channelshift.member_admin create-master --username local_master --email master@example.com
```

비밀번호는 화면에 표시하지 않고 두 번 입력받으며, 일치할 때만 계정을 생성한다. 비밀번호 명령행 인자나 환경변수는 지원하지 않는다. 숨김 입력을 보장할 수 없는 터미널·파이프에서는 생성을 거절한다. 회원 서버와 같은 저장소의 `members/accounts.sqlite3`를 사용하고 성공 시 `master_created`를 출력한다. SMTP 설정이나 메일 발송은 필요하지 않다.

마스터는 저장소에 하나만 생성할 수 있다. 기존 마스터가 있거나 아이디·이메일이 이미 사용 중이면 중단하며 기존 계정을 승격하거나 비밀번호를 덮어쓰지 않는다. 웹 가입 요청으로 마스터를 생성할 수 없다. 로컬 생성 시각과 이메일 인증 시각은 별도 값이다. 로컬 생성은 이메일 소유권 인증이 아니므로 `email_verified`는 `false`이고 `verified`는 비어 있다. 일반 인증 메일 재발송·인증 흐름으로 마스터 비밀번호를 변경하지 않는다.

마스터도 일반 회원처럼 자신의 작업공간에서 프로젝트 작업을 할 수 있다. `/admin`에서 회원 목록과 이메일 인증 상태를 확인하고, 사유를 입력하여 일반 회원을 정지·복원하며, 최근 관리 감사 기록 100개를 조회한다. 정지하면 해당 회원의 모든 기존 세션이 폐기되고 새 로그인도 차단된다. 복원 후에는 다시 로그인해야 한다. 마스터 자신은 정지할 수 없다. 관리 작업은 서버와 데이터베이스 트랜잭션 안에서 권한을 확인하며 일반 회원은 실행할 수 없다.

관리 감사 기록에는 로컬 마스터 생성과 회원 정지·복원의 시각, 실행자·대상 ID, 동작, 사유를 저장한다. 비밀번호·해시·세션 토큰은 조회 응답이나 감사 필드에 넣지 않는다. 관리 사유에도 비밀번호나 토큰을 적지 않는다. 타 회원의 프로젝트 내용 열람, 역할 승격 UI, 조직·초대·공유 기능은 아직 없다. 기존 운영자 자료나 호스트의 Codex 세션·API 비밀값을 마스터에게 자동으로 넘기지 않는다.

## 저장·시도 제한

비밀번호는 계정별 무작위 16바이트 salt와 scrypt(`N=2^17, r=8, p=1`, 출력 32바이트)로 저장한다. 메모리 상한은 호출당 256MiB이고 한 서버 프로세스에서 해시 작업은 동시에 하나만 허용한다. 슬롯을 얻지 못하면 기다리는 작업을 무한히 쌓지 않고 `auth_busy`로 거절한다. 없는 아이디의 로그인에도 같은 비용의 scrypt 계산을 수행한다. 실제 운영 장비의 지연·메모리 측정과 용량 계획은 후속 작업이다.

인증·세션 토큰은 각각 무작위 32바이트를 사용하며 DB에는 SHA-256 digest만 저장한다. 가입 API가 인증 토큰을 반환하지 않는다. 로그인 코어가 만든 세션 토큰은 HTTP 계층이 HttpOnly·SameSite 쿠키로 전달하며 응답 본문에는 넣지 않는다. 현재 localhost HTTP 모드는 공개 HTTPS 배포용 쿠키 구성을 대신하지 않는다. 인증 URL은 `/login#verify=...` 형식으로 토큰이 일반 URL 경로·쿼리에 들어가지 않게 한다. 프론트는 토큰을 읽은 뒤 주소창에서 제거해야 하며 비밀번호·토큰·메일 본문은 로그에 남기지 않는다.

세션은 8시간 후 만료되며 계정당 최대 5개다. 새 로그인으로 한도를 넘으면 가장 오래된 세션을 폐기한다. 세션별 로그아웃과 만료 검증은 구현되어 있으나 사용자가 모든 장치의 세션을 조회·철회하는 UI는 아직 없다.

로컬 파일럿의 제한값은 다음과 같다. 이는 서비스 공통 권장 처리량이 아니며, 공개 서비스에서 요구되는 사용자·IP·기기·네트워크 단위의 남용 방어를 대체하지 않는다.

| 동작 | 10분 동안 동일 대상 | 서버 전체 10분 동안 |
| --- | --- | --- |
| 가입 | 이메일당 3회 | 10회 |
| 인증 메일 재발송 | 이메일당 3회 | 10회 |
| 로그인 | 아이디당 5회 | 30회 |
| 이메일 인증 제출 | 토큰당 5회 | 30회 |

시도는 비싼 해시 계산 전에 SQLite에 기록하며 실패·서버 재시작 후에도 유지된다. 시도 기록 bucket은 512개로 제한하고 만료 전 용량이 부족하면 거절한다. 총 계정 1,000개, 일반 미인증 계정 100개가 상한이며 로컬 마스터는 미인증 계정 상한에서 제외한다. 여러 서버 프로세스의 해시 동시성 제한과 대규모 가입·메일 큐는 구현하지 않았다. 제한값에 도달한 공유 서버에서 다른 회원도 일시적으로 기다릴 수 있으므로 인터넷 공개 전 별도 설계가 필요하다.

회원 SQLite는 기존 저장소와 다른 디렉터리에 둔다. 새 POSIX 부모 디렉터리는 0700, DB는 0600으로 만들고 기존 파일의 소유자·권한·하드 링크와 경로의 심볼릭 링크를 검사한다. Windows에서는 reparse point를 거절하지만 POSIX mode 검사가 ACL을 검증하는 것은 아니다. 운영자 전용 사용자 프로필 아래에 두고 Windows ACL을 별도로 확인해야 한다. DB 접근은 매 호출 후 닫으며, 토큰 소비·고유 계정·세션 변경은 SQLite 트랜잭션에서 처리한다.

## 메일 설정

메일러는 `channelshift.member_mail.from_environment(base_url)`로 구성한다. 아래 항목이 전혀 없으면 `None`을 반환하고 가입을 차단한다. 일부만 있거나 비밀번호 파일이 없으면 시작 시 설정 오류를 반환한다.

| 환경변수 | 내용 |
| --- | --- |
| `CHANNELSHIFT_SMTP_HOST` | 운영자가 지정한 SMTP 서버 |
| `CHANNELSHIFT_SMTP_PORT` | STARTTLS 기본 587, SMTPS 기본 465 |
| `CHANNELSHIFT_SMTP_FROM` | 발신 이메일 주소 |
| `CHANNELSHIFT_SMTP_USER` | SMTP 인증 계정 |
| `CHANNELSHIFT_SMTP_PASSWORD_FILE` | 저장소 밖의 앱 비밀번호 파일 절대 경로 |
| `CHANNELSHIFT_SMTP_MODE` | `starttls` 또는 `smtps`; 기본 `starttls` |

비밀번호 원문은 소스·프로젝트·명령 인자·공개 `.env`에 저장하지 않는다. 전용 비밀번호 파일은 일반 파일이어야 하고 심볼릭 링크·하드 링크를 거절한다. POSIX에서는 파일 소유자와 0600에 준하는 비공개 권한을 확인한다. Windows ACL은 별도로 관리한다. 비밀번호 파일을 매 발송 시 다시 읽어 교체를 반영하며, 브라우저의 Gmail 로그인 세션을 재사용하지 않는다. Gmail을 사용할 경우 계정 정책에 맞는 앱 비밀번호를 별도로 설정해야 한다.

SMTP는 시스템 신뢰 저장소로 서버 인증서를 검증하며 STARTTLS 실패 시 평문으로 계속하지 않는다. 이메일 발송 오류는 주소·메시지·서버 응답·비밀값을 포함하지 않는 `email_delivery_failed`로 바꾼다. 등록 메일 발송 실패 시 아직 미인증인 해당 등록을 정리하고, 재발송 실패 시 새 토큰도 폐기한다. SMTP 수락 이후 실제 수신함 배달, 반송 처리, 큐 재시도, SPF/DKIM/DMARC 운영 점검은 이번 기능에 포함되지 않는다.

메일 링크의 origin은 요청 Host에서 만들지 않고 서버 설정에서 받는다. 어댑터는 HTTPS origin 또는 명시적인 `http://127.0.0.1:<port>`만 허용하고 자격증명·쿼리·경로가 들어간 base URL을 거절한다. 현재 회원 서버 실행기는 localhost origin만 사용한다. 실제 SMTP 전송이나 외부 서비스 연결은 단위 테스트에서 수행하지 않는다.

### Windows Gmail 도우미

저장소의 PowerShell에서 아래 도우미를 실행한다. 발신 주소는 `-Email`로 지정하거나 프롬프트에 입력한다. 개인 주소를 스크립트에 적을 필요는 없다.

```powershell
.\scripts\configure-gmail.ps1
.\scripts\start-members.ps1
```

설정 도우미는 앱 비밀번호를 `Read-Host -AsSecureString`으로 직접 입력받는다. Google 계정의 일반 비밀번호를 입력하지 않는다. 앱 비밀번호 화면의 구분용 공백은 제거한다. 비밀번호를 인자·출력·클립보드에 넣지 않으며 메일도 자동 발송하지 않는다.

설정은 `%LOCALAPPDATA%\ChannelShift\mail`의 `gmail-app-password.txt`와 `smtp.json`에 저장한다. JSON에는 발신 주소·서버·비밀번호 파일 경로 등 비밀 아닌 설정만 들어간다. 도우미는 해당 디렉터리·파일의 상속 ACL을 차단하고 현재 Windows SID에만 허용 규칙을 부여한 뒤 확인한다. 이는 평문 비밀번호 파일에 대한 접근 제한이며 암호화나 관리자·같은 사용자 계정의 접근 차단을 뜻하지 않는다. 경로의 reparse point를 거절하고 기존 비밀번호·설정 파일을 덮어쓰지 않는다. 설정 도중 실패해 일부 파일만 생겼으면 상태를 확인하고 운영자가 정리한 뒤 다시 실행해야 한다.

실행 도우미는 저장소의 `.venv\Scripts\python.exe`를 사용한다. 다른 환경은 `-Python 'C:\absolute\path\python.exe'`로 명시한다. `-Port`로 포트를 바꿀 수 있고 기본은 5189다. 전용 설정이 없으면 SMTP 환경변수를 비운 미설정 상태로 실행하여 가입을 차단한다. 설정이 있으면 경로와 ACL을 확인하고 비밀 아닌 SMTP 항목만 자식 프로세스 환경에 전달하며, 종료 후 원래 환경변수를 복원한다.

설정을 추가하거나 변경한 뒤에는 이미 실행 중인 회원 서버를 재시작해야 적용된다. 설정 저장·스크립트 파서 검사·메모리상의 ACL 구성 검증은 실제 Gmail 인증이나 메일 배달 성공을 의미하지 않는다.

## 직원·고객·마케팅 업체의 권한

직원, 고객, 마케팅 업체 모두 일반 회원으로 가입한다. 운영자가 로컬에서 직접 생성하는 마스터만 회원 관리 권한을 갖는다. 가입 화면의 분류 선택이나 이메일 문자열만으로 직원·관리자 권한을 부여하지 않는다. 회원 작업공간은 서버가 인증한 계정 ID로 분리하며 기존 운영자 자료를 첫 가입자나 마스터에게 자동 귀속하지 않는다. 회원별 명시 연결·권한 부여가 없는 운영자의 Codex 세션이나 유료 모델 API 키를 회원에게 제공하지 않는다.

후속 조직 모델은 `organization → membership(owner/admin/editor/viewer) → project`를 기준으로 설계한다. 마케팅 업체가 여러 고객 프로젝트를 관리하려면 고객별 초대와 명시적 공유가 필요하다. 서로 다른 고객과 다른 마케팅 업체의 자료는 기본적으로 분리되어야 한다. 플랫폼 관리자의 고객 자료 열람도 별도 권한·감사 기록·사용자 고지를 요구한다. 현재의 마스터·일반 회원 구분은 회원 관리에만 적용하며, 조직·초대·프로젝트 공유 역할·타 회원 프로젝트 열람 기능은 구현하지 않았다.

## 검증 범위와 미완료 항목

`tests/test_member_auth.py`는 미인증 로그인 거절, 인증 토큰 만료·재사용·재발송, 인증 시 비밀번호 교체, 중복·동시 가입, 동시 인증의 단일 소비, 메일 미설정·실패, 해시 전 영구 시도 제한, 세션 만료·철회·개수 제한, 입력 경계, SMTP TLS·오류 비공개 처리를 확인한다. 실제 scrypt 두 번을 실행하여 설정을 검증하고 나머지 상태 전이 검사는 빠른 테스트용 함수로 해시 계산만 대체한다. Windows에서는 POSIX 파일 권한 검사를 실행하지 않는다. HTTP·쿠키·계정별 작업공간 경계는 별도 HTTP 테스트의 책임이다.

`tests/test_member_admin.py`는 단일 마스터 동시 생성, 기존 계정 보호, 일반 회원의 관리 거부, 마스터 이메일 인증 상태 보존, 정지·복원과 세션 폐기, 정지와 로그인 경합, 감사 기록·안전한 조회 필드, 기존 DB 이전을 확인한다. `tests/test_member_admin_cli.py`는 임시 저장소와 숨김 입력 모의 호출로 생성·입력 불일치·비대화형 입력 거부·오류 비공개 처리를 확인한다. 테스트에는 실제 개인 자격 증명을 사용하지 않는다.

비밀번호 재설정·변경·유출 비밀번호 검사, MFA/passkey, 분실 계정 복구, 이메일 변경·계정 삭제, 사용자의 전체 세션 관리, 조직 권한·초대·공유, 프로젝트 접근 감사·남용 모니터링, 운영 메일 큐, 공개 HTTPS 배포는 후속 작업이다. 이 미완료 항목을 구현했다고 표시하거나 이메일 인증만으로 보안 검수가 끝났다고 판단하지 않는다.
