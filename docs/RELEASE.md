# v0.1.0 · Independent ChannelShift

Verification date: 2026-09-29. This release starts a new independent implementation; the earlier AGPL application and interim adapter are not release inputs.

## Included

- Original logical schema model, strict validation and four starter templates.
- PostgreSQL/MySQL/SQLite DDL exporters and Java 17+/Jakarta JPA/Spring Data source generation.
- Eight local stdio MCP tools using official SDK 2.2.0.
- Original dependency-free browser editor and bounded loopback HTTP API.
- Topic/project-classified immutable local versions, native JSON and separate development skill.

## Verification

```text
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe -m pip check
node --check src/channelshift/web/app.js
.venv/Scripts/python.exe scripts/build-release.py
```

The standard suite ran 40 tests: 39 passed, one opt-in Java compile check skipped. That compile check was run separately with actual Jakarta Persistence 3.1.0, Spring Data JPA 3.5.0 and Spring Data Commons 3.5.0 API jars: **84 generated classes compiled successfully with javac --release 17**. Jars were downloaded to a temporary test directory and are not distributed. Set `CHANNELSHIFT_JAVA_TEST_CLASSPATH` to the actual API jar classpath and put javac on PATH when running the optional test in `tests/test_core.py`.

Tests cover four starters across three SQL dialects, actual SQLite schema creation and FK enforcement, composite/cyclic references, malformed types and limits, identifier/default escaping, Java names and literals, immutable storage/corrupt-file handling, HTTP Host/Origin/token/body guards, and all eight tools through an actual official SDK stdio client. Dependency consistency (`pip check`) passed.

Browser checks used synthetic schemas and separate temporary storage: template generation, validation, SQL/Java preview, native field rename reflected in SQL, save/reload, in-page cancel confirmation preserving work, and narrow-screen layout. A downloaded Customers.java file matched the generated bytes. Browser-captured warning/error logs were empty for these flows. Native blocking confirms were replaced with accessible HTML dialogs; editable fields now update the model on input.

No PostgreSQL or MySQL server execution was performed. Java compilation validates generated source/API compatibility; it does not prove a configured Spring application connects successfully or enforces a business workflow. Structural validation does not validate operational migration safety or authorization policies.

## Artifact boundary

The Python wheel contains editable original Python/HTML/CSS/JavaScript and license notices, not vendored SDK/native dependencies. The source archive includes source, tests, skill and license inventory. The skill ZIP contains the skill, installation helper and that wheel. SHA256SUMS.txt identifies the uploaded artifacts.

Git and nested archive scans exclude credentials, personal server destinations, user home paths, runtime schema stores, browser profiles, old frontend bundles and the AGPL prototype. The SDK dependency inventory describes a verified installation snapshot, not a claim that all transitive source has been manually audited or all dependencies have identical licenses.

## Initial limits

No live DB execution, NoSQL, remote sync or legacy drawDB import is included. The existing installed app and its authorized private synchronization are preserved separately. App-assigned IDs, timezone-free timestamps with a UTC convention and database-specific type limitations are explained in generated SQL/Java guidance. UI saves are explicit versions, not automatic browser-draft backups.

GitHub release is the distribution target. No npm/PyPI registry release or public web endpoint is created.
