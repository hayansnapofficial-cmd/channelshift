# 본인 Codex 구독으로 홈페이지 제작

상태: 전체 연결 설계와 요구사항 접수 파일럿. 기존 ChatGPT 로그인으로 로컬 Codex CLI의 자연어 후보 작성을 구현·시험했다. 프로그램 내 로그인 UI와 전체 제작 실행기는 아직 구현되지 않았다. 현재 사용법은 [접수 파일럿](INTAKE_PILOT.md)을 따른다.

## 확정한 사용자 흐름

직원은 고객의 요구사항을 자연어로 입력하고 프로그램에서 본인 Codex에 로그인한다. 채널쉬프트가 요구사항 정리부터 화면·데이터·API 설계, 구현, 검수, 납품 준비까지 필요한 작업을 같은 계정의 Codex에 순서대로 전달한다. 직원이 단계마다 프롬프트를 복사하거나 기술 설정 양식을 처음부터 작성하는 제품이 아니다.

자연어 입력 → 요구사항 초안·누락 질문·확인 뒤 시스템 설계와 디자인 후보 제작을 두 흐름으로 진행한다. 시스템 설계·승인 디자인·고객 요구사항의 정합성 검수 뒤 DB 구축·검수 → 백엔드·검수 → 프론트·통합검수 → 배포·인계로 이어진다. 비용·고객 정책·업무 판단을 Codex가 추측해 확정하지 않으며, 필요한 결정만 쉬운 질문으로 묶는다.

## 계정과 실행 위치

| 구분 | 역할 |
| --- | --- |
| 채널쉬프트 회원 | 프로젝트 소유권, 팀 구성, 저장 자료, 검수·납품 기록 |
| 직원 본인의 Codex 연결 | 해당 직원에게 허용된 모델·구독 한도로 제작과 수정 수행 |
| 직원 PC의 실행 연결부 | Codex 통신, 프로젝트 파일, 허용된 개발 DB·테스트 실행 |
| 채널쉬프트 서버 | 허용된 프로젝트 산출물·단계·증거 동기화; Codex 토큰 수집·공유 없음 |

첫 구성은 설치 프로그램 또는 웹 화면에 연결된 로컬 동반 프로그램이다. 브라우저만으로 로컬 Codex 프로세스를 직접 실행할 수 있다고 가정하지 않는다. 원격 웹 화면에서 작업하려면 인증된 동반 프로그램 연결이 있어야 하며, 연결되지 않으면 실행 불가 상태를 표시한다.

같은 PC에서 채널쉬프트 회원을 바꿀 때 연결된 Codex 계정을 자동 승계하지 않는다. 계정 연결을 다시 확인하고, 직원별 OS 계정 또는 분리된 실행·인증 저장소를 사용한다. 운영자가 여러 직원의 구독을 모아 공유 실행하는 구조로 만들지 않는다. Codex 로그아웃/계정 교체는 다른 Codex 클라이언트에도 영향을 줄 수 있으므로 범위를 표시한다.

## 공식 연결 방식과 확인 범위

공식 [Codex App Server](https://learn.chatgpt.com/docs/app-server)는 제품 안의 인증·대화·승인·실행 이벤트 연동을 제공한다. [인증 문서](https://learn.chatgpt.com/docs/auth)는 ChatGPT 로그인에 따른 구독 사용과 API 키의 사용량 과금을 구분한다.

설치된 CLI `0.158.0-alpha.2.1`의 도움말과 생성된 JSON Schema에서 다음 메서드의 존재를 2026-09-29 확인했다. 이는 실제 로그인·생성 성공 또는 모든 버전의 호환성 확인은 아니다.

| 메서드 | 연결부에서 사용할 목적 |
| --- | --- |
| `account/login/start` | Codex가 관리하는 ChatGPT 브라우저 로그인 시작 |
| `account/read` | 활성 계정·인증 방식 확인 |
| `account/rateLimits/read` | 조회 가능한 한도·초기화 시각 확인 |
| `thread/start` | 허용된 프로젝트와 작업 정책에 연결된 작업 생성 |
| `turn/start` | 단계 입력과 변경 범위를 전달 |
| `turn/interrupt` | 중단 요청; 실제 정지·부작용은 별도 확인 |

초기 후보는 로컬 stdio App Server 연결이다. 공식 문서에서 App Server가 실험적이며 프로덕션 워크로드 지원 제한을 명시하므로, CLI·프로토콜 버전을 고정한 내부 파일럿과 호환성 시험부터 진행한다. 공개 운영 적합성은 별도 출시 조건이다. 비대화형 CLI는 기능을 검증한 경우에만 같은 구독 인증을 사용하는 대체 구현으로 검토한다.

## 연결 동작의 계약

1. 채널쉬프트가 Codex 실행 파일의 버전과 지원 메서드를 확인한다. 실행 경로·인수는 검증된 설정에서 정하고 자연어를 셸 문자열에 삽입하지 않는다.
2. 직원이 ‘내 Codex 연결’을 선택하면 공식 로그인 페이지를 연다. 비밀번호 입력과 인증은 Codex가 처리하며 채널쉬프트 로그인 폼으로 받지 않는다.
3. 로그인 성공 이벤트 후 활성 인증 방식이 구독 경로인지 확인한다. API 키나 다른 Provider라면 작업을 시작하지 않고 다른 연결이 선택됐음을 설명한다.
4. 요구사항 원문과 선택 자료가 Codex로 전달됨을 작업 화면에 표시한다. 직원이 연결한 계정의 데이터 처리 정책이 적용된다. 플랫폼 자료 재사용 동의와는 별개다.
5. 로컬 연결부는 변경 범위·작업 ID·기준선과 관련 자료만 전달한다. 출력은 구조화된 후보 자료로 검사하고, 모델의 `approved` 문자열은 승인 기록으로 채택하지 않는다.
6. 일반 코딩 작업은 허용한 작업공간 정책 안에서 이어간다. Codex의 도구 실행 승인 요청과 홈페이지 단계 검수는 다른 사건으로 기록하며, 둘 중 하나를 다른 쪽 승인으로 바꾸지 않는다.
7. 연결 단절·한도 초과·인증 만료를 구분한다. 한도 초과는 현재 결과를 보관하고 `WAITING_FOR_QUOTA`로 두며 초기화 후 명시한 재개 정책에 따라 이어간다.
8. 새 시도 전 이전 실행·Writer·부분 DB 적용을 확인한다. 계정이나 요금제를 자동 교체하지 않고, 승인받지 않은 API 과금·크레딧 구매·한도 초기화를 실행하지 않는다.

실행 연결부는 인증 정보를 Codex 관리 저장소에 두고 서버·프로젝트·로그·납품 ZIP으로 내보내지 않는다. API 키 환경변수·다른 Provider 설정이 끼어들어 과금 경로가 바뀌는 경우를 탐지하며, ‘구독 전용’ 조건을 확인할 수 없으면 실행을 보류한다. 자연어가 승인자·대상 환경·실행 권한을 직접 지정하지 못하도록 프로그램 정책을 별도로 집행한다.

구독 한도·조직 정책·모델 이용 가능 여부에 따라 대기나 사용자 조치가 필요할 수 있다. 처음부터 끝까지는 **작업과 산출물의 연속성**이며 한 번에 무제한 실행된다는 약속이 아니다. 호스팅·DB·도메인·외부 서비스 비용은 Codex 구독과 별도로 취급한다.

## 출시 전 확인할 것

- 계정 A 연결이 다른 채널쉬프트 회원 B의 작업에 재사용되지 않는다.
- 로그인 취소·실패·만료에서 거짓 연결 완료 표시가 없다. 원문 토큰이 로그나 서버 전송에 포함되지 않는다.
- API 키·다른 Provider·모델 한도 부족에서 자동 우회가 없다. 한도 조회 실패를 무제한으로 표시하지 않는다.
- 사용자 자연어·모델 산출물로 승인·도구 정책·셸 인수를 바꿀 수 없다.
- 실제 Codex 한 작업의 시작·이벤트·중단·재개와 독립 검수 연결을 파일럿에서 확인한다.
- 실행 성공과 검수 통과, 배포 완료와 고객 인수 완료를 각각 구분한다.

초기 프로토콜 확인 뒤 `codex_intake.py`의 비대화형 CLI 연결을 구현했다. 실제 ChatGPT 구독 인증으로 합성 원문 후보 작성 1회를 확인했다. 이는 기존 로그인 활용이며 프로그램 내부의 로그인 시작·계정 전환·전체 제작·재개 기능까지 확인한 것은 아니다. 위 계약의 회원 연결·긴 작업·독립 승인 항목은 후속 구현 요구사항이다.
