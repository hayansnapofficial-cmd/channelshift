# 고객 원문 → Codex → Jev 접수 파일럿

2026-09-29 개발 브랜치 기능이다. 공개 v0.1.0 릴리스에는 포함하지 않는다.

## 실행과 사용

설치한 소스의 Python 환경에서 `python -m channelshift.web --port 5188`을 실행하고 `http://127.0.0.1:5188/delivery`를 연다. 기존 편집기에서도 **요구사항 접수** 링크로 이동한다.

1. 프로젝트명과 고객의 원문을 입력해 등록한다. 원문이 없으면 등록하지 못한다.
2. **Codex로 정리**를 누른다. PC의 Codex가 ChatGPT 구독 방식으로 로그인되어 있고 필요한 CLI 기능을 지원해야 한다. 최초 정리에는 원문을 전달하며 고객 저장소에서 작업하지 않는다.
3. 후보와 확인 질문을 검토하고 질문별 답변을 작성해 **답변 저장**을 누른다. 저장한 답변은 수정·재열람할 수 있다. 답변 수와 필수 미답변 수는 현재 후보를 기준으로 표시한다. 저장 자체는 로컬 기록만 남기며 모델 호출이나 승인이 아니다.
4. 저장한 답변을 반영하려면 **Codex로 정리**를 다시 누른다. 원문과 현재까지 저장한 답변 근거를 함께 전달한다. 작성 중인 미저장 답변은 전송하지 않는다. 인용문이 이 입력에 실제로 있는지는 코드로 검사한다.
5. 필요하면 **Jev 검토**를 누른다. 해당 후보 생성 당시의 고정된 입력과 후보를 TypeSafe API로 전송하며 별도 이용료가 적용된다. 그 후 저장한 답변이 과거 후보의 검토 근거를 바꾸지 않는다. 결과는 일치·근거 부족·모순·불명확의 참고 판정이다.
6. 직원이 판단한 이유와 결정, 결과를 **개입 기록**에 남긴다. 새로고침하거나 앱을 다시 열어도 저장 기록이 유지된다.

로그인은 현재 Codex 앱/CLI에서 먼저 수행한다. 프로그램 안의 새 로그인 화면과 App Server 기반 긴 작업 연결은 후속 구현이다. 이 파일럿은 요구사항 후보 작성까지 연결하며 와이어프레임·DB 구축·전체 홈페이지·배포를 실행하지 않는다.

## 질문 답변과 입력 근거

답변은 후보 생성 작업으로 구분한 버전, 질문 ID, 질문 내용 해시, 원문 해시와 함께 사건으로 추가한다. 수정·비우기도 새 사건이며 이전 답변을 덮어쓰지 않는다. 같은 내용의 후보가 다시 생성되거나 `Q-001`이 다른 질문으로 재사용되어도 답변을 자동 이월하지 않는다. **답변 이력**에서 현재·이전 후보의 질문과 저장 내용을 확인한다.

같은 질문에 다른 탭이 먼저 저장하거나 후보가 바뀌면 저장 요청은 HTTP 409로 거절한다. 브라우저는 입력 중인 답변을 유지하고 현재 저장값을 보여 준다. 현재 답변을 확인한 뒤 다시 저장할 수 있다. 후보가 달라진 초안은 이전 후보의 미저장 답변으로 남고 새 질문에 자동 연결되지 않는다. 미저장 초안은 현재 페이지 메모리에만 있으며 페이지를 닫거나 새로고침하면 사라진다.

재정리 입력에는 후보별 각 질문의 마지막 저장 답변을 별도 로컬 근거로 포함한다. 이전 후보를 만드는 데 쓰인 답변도 남기므로 새 후보에서 질문이 사라져도 다음 정리의 근거가 조용히 사라지지 않는다. 각 작업의 시작·결과 사건에는 실제 입력 문자열, SHA-256 해시, 사용한 답변 버전 참조를 고정한다. 원문은 그대로 유지한다. 로컬 작업자 답변은 인증된 고객 확인이나 배포 허가를 증명하지 않는다.

원문과 답변을 합친 모델 입력은 Unicode 문자 기준 12,000자까지이며 답변 한 항목은 2,000자까지다. 입력을 자르지 않는다. 합친 입력이 한도를 넘으면 실행 시작 전에 명확히 거절하고 이전 후보와 저장 답변을 유지한다. Codex 결과의 기존 128 KiB 한도도 유지한다. 이력 증가로 근거 전체가 한도를 넘는 경우 접수 범위를 재정리해야 하며 자동 요약·삭제로 우회하지 않는다.

API `POST /api/delivery/answer`는 `project_id`, `candidate_revision`, `question_id`, `question_digest`, `answer`, `expected_revision`만 받는다. 질문별 조회 결과의 `answer_revision`을 `expected_revision`으로 보낸다. 토큰·Origin 보호는 기존 로컬 API와 같다. 성공 응답은 갱신된 프로젝트이며 별도 모델 호출을 하지 않는다.

## 사람 개입을 남기는 이유

프로젝트의 **동의 화면** 설정에서 미결정·사용·사용 안함을 선택하고 선택자 표기와 이유를 저장할 수 있다. 기본값은 미결정이다. 선택자 표기는 신원 인증이 아니며, 저장 자체로 추적 기능을 켜거나 법적 동의·검수 통과를 선언하지 않는다. 법·서비스 필수 동의는 별도 검수한다.

설정 변경은 서버 시각과 이전·새 버전 해시를 가진 사건으로 추가하며 **변경 이력**에서 확인한다. 원문을 먼저 등록해야 설정할 수 있고, 다른 탭이 먼저 저장하면 409로 거절하며 작성 중인 값은 유지한다. 브라우저의 미저장 설정은 프로젝트별로 분리하되 페이지를 닫으면 사라진다. 설정 버전은 개입 기록의 판단 근거에도 포함된다. API `POST /api/delivery/consent`는 `project_id`, `mode`(`undecided`·`required`·`not_required`), `operator_label`(필수, 100자), `reason`(필수, 2,000자), `expected_revision`만 받는다.

프로젝트와 원문, 해당 작업 ID, 후보 해시, 당시 상태에 다음 기록을 연결한다.
메모를 작성하는 동안 후보·작업·판정 기준이나 저장 답변이 바뀌면 저장을 보류하고 최신 결과를 다시 확인하게 한다. 현재·이전 후보의 최신 답변 버전 참조를 해시로 묶어 개입 기록의 판단 근거에 연결한다. 입력한 메모는 보존하며 다른 버전에 조용히 연결하지 않는다.

| 항목 | 내용 |
| --- | --- |
| 단계 | 접수·요구사항·화면·DB·백엔드 등 개입한 단계 |
| 이유 | 고객 자료 부족, 요구사항 모순, AI 오류, 표준 밖 요청, 권한 확인, 품질 문제, 기타 |
| 상황 | 왜 자동으로 진행할 수 없었는지 |
| 결정 | 사람이 어떤 판단·수정을 했는지 |
| 결과 | 이후 확인된 결과; 아직 모르면 비워 둠 |

현재 기록자는 로컬 작업자로 표시한다. 이 필드는 인증된 선임 신원이나 승인 권한을 증명하지 않는다. 기록을 저장해도 단계 승인이나 배포 허가는 생기지 않는다.

실행 시작·결과·실패에는 작업 ID와 소요 시간을 남긴다. 후속 분석에서는 단계별 개입 빈도·원인, 수정 후 재발률·품질을 함께 본다. 개입 횟수만 적다는 이유로 자동화 성공으로 평가하지 않는다. 직원 개인 감시나 회원 간 AI 학습 자료로 자동 전송하지 않는다.

## 저장·실행 범위

- 저장소는 `CHANNELSHIFT_HOME` 또는 `~/.channelshift` 아래의 `delivery.sqlite3`다. 기존 DB 설계 파일 저장과 분리한다.
- 원문과 이전 후보·Jev 결과·답변·개입 사건 및 모델 입력 스냅샷을 보존한다. 화면에는 최근 후보와 답변 이력을 보여 준다. 원문 수정·삭제 API, 같은 프로젝트에 새 SRC 추가, 보존 만료 기능은 아직 없다. 실제 고객 자료를 대규모로 넣기 전 필요한 보존·삭제 정책을 구현해야 한다.
- 실행은 한 번에 한 작업이다. 새로고침은 재실행하지 않는다. 실패 시 기존 후보를 남기며 자동으로 API 계정이나 모델을 바꾸지 않는다.
- 앱이 비정상 종료되어 실행 중 기록이 남으면 다음 작업을 차단한다. 이전 실행 종료 확인과 복구 UI는 후속 범위이며 임의 시간 만료만으로 작업을 재배정하지 않는다.
- 로컬 Host·Origin·프로세스 토큰 보호를 적용한다. 여러 회원을 위한 서버 권한 체계는 아직 없으므로 인터넷에 공개하는 서버가 아니다.

## Codex와 Jev의 역할

Codex는 원문과 명시적으로 반영한 답변 근거를 읽어 요구사항 후보와 질문을 작성한다. Jev는 해당 후보가 생성 당시 입력과 맞는지 작은 판단을 병렬로 수행한다. 근거가 없는 인용은 API 호출 전에 코드가 거부한다. Jev의 높은 확신 값은 고객 승인이나 테스트 통과가 아니다.

2026-09-29 합성 원문으로 실제 호출을 확인했다. Codex 구독 호출 1회는 18.55초에 후보 3개·질문 5개·범위 항목 1개를 반환했다. 별도의 Jev 호출은 0.34초에 후보 2개를 판정했고, 원문 일치와 의도적으로 뒤집은 부정문 모순을 구분했다. 이는 서로 다른 작업의 단일 측정이며 속도 배율·정확도 보장이 아니다.

Jev 구현은 [공식 HTTP API](https://docs.typesafe.ai/api)와 [코딩 에이전트와의 역할 구분](https://docs.typesafe.ai/introduction/coding-agents)을 따른다. [인용 검토 패턴](https://docs.typesafe.ai/cookbooks/citation_check)은 문자열 존재 확인 뒤 의미를 검토하는 참고 자료다. 실제 프로젝트에서 판정 품질을 평가하기 전 자동 승인 임계값을 적용하지 않는다.

## 설정

Codex는 설치된 `codex` 실행 파일을 사용한다. 현재 검증한 CLI는 `0.158.0-alpha.2.1`이며 필요한 기능이 없는 버전에서는 실행을 보류한다. API 키·다른 Provider 환경이 있으면 구독 전용 조건을 확인할 수 없어 중단한다. 비밀 환경변수는 자식 프로세스에 전달하지 않는다.

Jev 키는 서버 프로세스의 `TYPESAFE_API_KEY` 또는 Windows 사용자 DPAPI로 암호화한 `%LOCALAPPDATA%/ChannelShift/credentials/typesafe.dpapi`에서 읽는다. 키 원문을 브라우저·Git·설계 JSON에 넣지 않는다. 모델은 `jev-latest`를 요청하고 실제 응답 모델 이름을 결과에 기록한다. 재현성이 필요한 운영 버전에서는 검증한 모델 버전을 고정해야 한다.

Apify 연동은 아직 없다. 외부 참고 사이트 수집이 필요한 프로젝트에서 별도로 추가할 수 있으며 제작 흐름의 필수 의존성으로 두지 않는다.
