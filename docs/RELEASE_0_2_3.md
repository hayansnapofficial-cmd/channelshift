# ChannelShift 0.2.3

새 프로젝트에서 직원이 기능을 빠뜨리지 않도록 선택 카드와 Codex 추천을 제공합니다.

- 문의·예약·회원·결제·콘텐츠·알림·디자인·검색/공유의 여덟 카드와 항상 보이는 자유 설명란.
- ‘잘 모르겠어요’를 누르면 저장한 요구와 설명을 바탕으로 본인 Codex가 추천 이유·고려할 점을 제안. 직접 수락한 뒤 저장·재분석해야 명세에 반영.
- 미선택·보류 항목과 재분석하지 않은 변경이 남아 있으면 요구사양 확정 차단.
- 프로젝트별 기능 카탈로그, 디자인·구현·문서 검수 가이드의 버전과 내용 해시 고정.
- 참고 사이트 수집과 요구사항·기능·참고자료·산출물 보조 점검. 기존 서버 자격증명과 공용 한도 사용, 자동 승인과 분리.

## 기존 프로젝트와 복구

회원·원문·답변·설계·승인·Codex 연결을 보존합니다. 기존 프로젝트를 열기만 해도 새 선택 카드를 강제로 적용하지 않습니다. 새 흐름은 새 프로젝트부터 기본 적용합니다. 기능 데이터는 기존 프로젝트/이벤트 저장소에 추가되며 기존 테이블의 파괴적 변환은 없습니다.

배포 전 진행 작업이 없는지 확인하고 프록시·회원 프로세스를 잠시 중지해 데이터·설정·연결 파일을 보호된 경로에 백업합니다. SQLite backup API와 무결성 검사를 사용하고 재시작 전후 기존 레코드 및 비DB 파일의 해시를 비교합니다. 이전 이미지 0.2.2를 보존합니다. 실패 시 먼저 이전 이미지·설정으로 복구하며, 배포 뒤 생긴 새 작업은 자동으로 지우거나 백업으로 덮어쓰지 않습니다.

0.2.3에서 새 기능 선택 프로젝트를 만든 뒤 0.2.2로 내리면 이전 코드는 새 선택·가이드 이력을 해석하지 못합니다. 이 경우 공개 유입을 멈추고 신규 데이터를 보존한 상태에서 수정 버전을 적용하거나 별도 데이터 복구를 판단해야 합니다. 배포 중 자동 복구는 새 공개 요청을 받기 전 검사 구간에 한정합니다.

## 검증 범위

Windows Python 전체 567개 중 562개 통과·환경 조건에 따른 5개 건너뜀, Node UI 회귀 검사 8개 통과. 브라우저에서 합성 모델 응답으로 추천 요청·명시적 수락·저장·재분석·확정·화면 설계, 참고자료 수집과 보조 점검을 확인했습니다. 배포 설치 이미지의 Linux 검사는 전환 전에 별도로 수행합니다.

추천과 보조 점검은 실제 기능 실행·보안 인수 검사·고객 승인을 의미하지 않습니다. 서버를 배포하면서 실제 고객 자료를 모델에 보내거나 이메일·유료 API를 시험 호출하지 않습니다. 기존 생성 앱 실행·납품 범위는 유지합니다.
